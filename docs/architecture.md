# Gaha Diwali Studio — architecture

Gaha Diwali Studio, maintained by Gaurav, runs entirely in the browser. Preview interaction is available immediately. A prior enabled-camera preference can resume only when the browser reports an existing grant; otherwise camera access starts only after a user click.

## Rendering and input

`main.ts` owns the application, collection selection, accessible controls, camera states, previews, keyboard input, and recording UI. The default HUD is a small header toolbar and a single illustrated dock; the gesture and keyboard guide is an on-demand native dialog. `fireworks/catalog.ts` is the collection's shared metadata; `crackerArt.ts` supplies material thumbnails for the selectors. `casingArt.ts` generates and caches 256-pixel Canvas sprites with matte paper grain, cylinder/sphere shading, cardboard rims, and projected jute cord. Ground effects reuse the same sprites with one image draw per frame.

`VideoCompositor` draws a star field or a mirrored camera feed at its original brightness and color. The camera draws directly into the stage without the former brightness/contrast/saturation filter, blue tint, intermediate frame canvas or vignette. `coverTransform.ts` supplies shared camera geometry to the compositor and `VisionEngine`. Every screen uses full-stage cover fitting, with controls overlaid rather than space reserved above or below the camera. Screen/camera aspect-ratio differences crop the edges; both consumers use identical geometry. Window and visual-viewport resizing update the canvas. CameraSession updates constraints on orientation changes without reopening the existing stream. Portrait capture prefers portrait dimensions and requests uncropped capture when available.

`display/fullscreen.ts` requests native fullscreen directly from a user tap, then attempts landscape locking on touch devices. Unsupported fullscreen opens Home Screen installation guidance; rejected requests show feedback. Orientation-lock failure preserves successful fullscreen and allows manual rotation. The manifest requests standalone/fullscreen display and landscape; Apple web-app metadata supports Home Screen launch. There is no service worker or offline cache. Mobile controls overlay a full-bleed camera: four small toolbar buttons, a 58px two-row portrait tray or 54px single-row landscape tray, and no creator footer. Capture and creator links remain available in the guide.

`VisionEngine` prefers a module worker (`visionWorker.ts`) with an OffscreenCanvas. `landmarkerLoader.ts` uses the module WASM loader in a worker and the classic loader in the main-thread fallback. A single resized ImageBitmap (longest edge 512px, adaptively 384/320px on slow inference) is in flight; frames are never queued, and bitmaps close after inference or cancellation. Epoch checks discard late results after camera/tracker resets. Worker initialization, failure, and cancellation preserve the existing camera lifecycle. The main-thread fallback is lazy-loaded so capable browsers do not parse its model runtime on startup. A runtime worker or bitmap-transfer failure triggers one bounded recovery on the paced main-thread path without touching the camera stream; the failed worker path is not retried by that engine. Repeated failure requires manual retry. The UI only announces live tracking after a usable result, rather than just model creation. Cold inference has an eight-second watchdog allowance; tab restoration resets the pending watchdog and invalidates old-epoch results without re-requesting camera access. `VisionEngine` processes a video frame only when its timestamp advances and the inference interval permits. Camera input uses requestVideoFrameCallback when available, and newer frames arriving during inference are coalesced to the most recent media timestamp. A completed result can immediately submit that latest frame; duplicate timestamps never re-run inference. API detection alone does not establish callback health: a 200ms watchdog falls back to polling an advancing video clock if callbacks are silent, throw, or repeatedly report an unchanged media timestamp. A callback/polling handover rejects equal or older frame times to avoid duplicate inference. Pose projection/event consumption runs on every visible animation tick independently of the fireworks paint gate. Detection targets 24–30 Hz and slows further when inference is expensive, with no backlog. Capture timestamps return from the worker for end-to-end request age, measured updates/s and stale-result rejection with a measured-cost freshness window (250 ms normally, at most 600 ms for slow inference). `handMotion.ts` predicts only palm translation for up to 70 ms and half a palm width, leaving raw finger geometry and gesture classification unchanged. Stops, reversals, missing hands and long gaps reset velocity. One-shot gesture results are returned once. Continuous results remain available between camera frames. `handGeometry.ts` uses world-space joint angles and hand-relative pinch distances to classify fingers as extended, folded, or uncertain. `GestureClassifier` maps nine effects to single-hand poses and the finale to two open palms, rejects uncertain required joints and downward/sideways fingers, and recognizes image-space thumb/index contact with separate enter/release thresholds. Contact outside the knuckles works with other fingers folded; a natural OK sign also works with its other fingers raised. Palm recognition uses 2D finger reach along the palm axis, accepts tilted/spread hands and uncertain depth estimates, and still requires all four non-thumb fingertips beyond their knuckles with an upward-facing hand. Rocket uses one finger, Roman candle two, Anar a fist, Phooljhadi a pinch, Starburst an L, Chakri one open palm, Sutli three fingers, Bullet thumbs up, and Ganga Jamuna index/little fingers. Both common ways to count three trigger Sutli. Holds are 180 ms normally, 70 ms for the sparkler, 220 ms for Chakri, and 250 ms for Sutli. Two open palms take priority and stabilize for 300 ms; a 220 ms pair-dropout grace prevents accidental wheel ignition. Chakri and Sutli repeat every 650 ms so their finite effects can overlap. Other single-hand signs retain independent holds/cooldowns. Per-type cooldowns prevent repeated reports. Missing hands clear pending holds.

`FireworkDirector` appends every manual ignition without a global input cooldown. Dock and hotkey launches use successive horizontal lanes; canvas taps retain their chosen coordinates. Each hand sustains its own fountain/sparkler. Both Anar and Phooljhadi keep their identity through a 220 ms tracking grace, follow available palm landmarks during classification gaps, and stop on a new sign or prolonged loss. Matching signs adopt active manually lit objects instead of creating stationary duplicates. Manual continuous emitters retain independent 3.5-second lives until adopted. Finite movable effects use per-hand bindings and the candidate pose metadata on HandPose, so positions update even while the discrete event is on cooldown. Ganga Jamuna forwards motion to its internal fountain; Roman candle shots already in flight remain independent. Every instance has an independent lifetime, while the shared particle pool remains bounded. It advances effects and the particle pool in fixed 1/60-second steps, then renders cracker bodies and particles once per display frame. Painting is capped at 60 Hz independently of high-refresh displays, and hidden pages skip simulation and inference. The catch-up interval is capped at 100 ms to avoid a long backlog after a background tab resumes.

## Camera permissions and readiness

`CameraSession` owns a single live stream and coalesces simultaneous startup requests. A running stream is reused when playback needs to resume. Readiness requires decoded video dimensions and a current frame, not just resolution of `getUserMedia`. An 8-second playback watchdog reports camera failures, while an unanswered browser permission request stays pending without retries. Cancelling startup releases a late-arriving stream. Track interruption events update the UI.

`cameraPreference.ts` remembers intent, not permission. Automatic resume requires both the stored enabled preference and `Permissions.query({name: 'camera'})` returning `granted`. Denied, prompt, unavailable, and unsupported query states never initiate automatic access. Turning the camera off saves an explicit off preference. The page does not modify browser or OS permissions.

Camera acquisition and tracking initialization are separate. Model or inference failures pause tracking and offer a tracking-only retry while retaining healthy video. Trackers coalesce concurrent initialization and can reset gesture history without closing the camera. Back/forward restoration resumes the application without forcing another page reload.

The camera video remains in layout at one pixel behind the stage so video decoders can deliver frames; it is never used as the visible preview. Camera-off, startup, interruption, permission, and tracking states have a dismissible status panel.

## Effects

Gesture mappings are documented in the README and shared catalog. Physical casings use cached material rendering; spark simulation is independent of those assets. Anar uses fine metal jets and a pressure ramp; Rocket climbs more gradually; aerial shells use a projected spherical distribution with depth-dependent size and exposure. Stars cool toward ember orange late in their life. Flicker uses coherent burn rhythms instead of independent frame randomness.

- `GangaJamuna`: Runs the original Anar fountain for 2.65 seconds with silver blossoms, sputters for 0.3 seconds, then invokes `groundBurst` and its own report.
- `Chakri`: Uses paired tangential spark jets, elliptical ground motion, acceleration, and a final spin-down. Duration: 4.2 seconds.
- `Bomb`: Shared fuse sequencing for Sutli and Bullet. Sutli uses a longer fuse and more powerful ground burst. The visible wrappers and audio reports differ.
- `groundBurst`: A brief flash, irregular low-angle fragments, and drifting smoke. This is visually distinct from an aerial peony; there is no decorative pressure ring.

The particle pool has 7,500 preallocated objects, a stack of free indices, and a packed list of live references. Simulation and rendering iterate only live particles. Expiry uses swap removal, including when crackles spawn replacement particles. Budget reductions thin existing particles across emitters and preserve reusable slots. Up to 192 slots can hold smoke, keeping its cost bounded. `GpuSparkRenderer` draws analytic, antialiased light profiles in one instanced WebGL2 pass; it has no bitmap spark heads. Trail width and intensity taper along the exposure. Sparks use a warm core while hot and retain their chemical color before cooling. The transparent GPU canvas is composited into the main 2D canvas, so capture includes the result. A soft sprite atlas with batched trails provides a Canvas 2D fallback if GPU initialization fails or its context is lost. Smoke and grouped ambient glows use cached sprites. The static sky is cached; the natural-color camera draws directly into the stage without a grading pass. `performance/quality.ts` selects high/balanced/low budgets from device hints, then steps down after sustained slow frames or worker latency above 80 ms and recovers slowly. Recovery requires tracking latency below 55 ms as well as healthy painting, prioritizing input under GPU contention. Pixel budgets are 3,686,400 / 1,440,000 / 786,432; particle budgets are 7,500 / 3,600 / 1,600. Low mode targets 30 fps, with a 24 Hz tracking target and 16 smoke particles. `renderScale.ts` honors device pixel ratio up to 2 within the selected budget. WebGL draws and composites in the same task, so drawing-buffer preservation is disabled.

## Sound

`PyroAudioEngine` downloads MP3 recordings early without creating an audio context. The first trusted pointer/touch/click/key event creates and explicitly resumes the audio graph; the dedicated sound button activates it without immediately muting it. Decoding is shared per sample. One-shot requests wait briefly for their first recording, coalesce by sound key, and respect explicit mute. Loop pulses retry naturally once decoding completes. State-change feedback, visibility restoration and camera startup handle suspended/interrupted contexts without requiring an off/on toggle. One-shots use randomized pitch; fountains, sparkler, and Chakri use pulse-driven loops and an inactivity watchdog. Sources are started before a scheduled stop, and completed one-shots disconnect their nodes.

The existing spinner recording is now connected to Chakri. The new bomb reports are mixes of existing recordings: Sutli has a deeper, longer layered report; Bullet combines thunder and heavy-impact samples at increased levels, replacing the previous thin pop mix. They are not newly recorded individual firecrackers. Ganga Jamuna transitions from the Anar loop to a distinct report. A shared compressor feeds both playback and recording.

## Capture

`CaptureEngine` captures the canvas at a requested 60 fps. It clones the audio track so recorder cleanup does not stop the shared audio destination. WebM/VP8 is preferred, with other supported WebM and MP4 options as fallbacks. Download extensions derive from the final MIME type. A finalizing state prevents one recording's completion from interfering with the next.

The finale greeting is composited into the canvas. Decorative HTML garlands, mandala, and diyas remain display-only. A PNG postcard adds its own greeting and the Gaha · by Gaurav signature. The render loop draws the same creator signature into the canvas while recording, so video exports include branding without capturing the HTML HUD. `branding.ts` supplies exported-media identity and filename prefixes.

## Verification

For local drawing diagnostics, open the app with `?profile=1`. The stage canvas exposes `data-spark-renderer` and a once-per-second `data-render-profile` summary of paint cadence, CPU submission time, and visible spark count. CPU submission time does not measure GPU execution time. The canvas also exposes `data-quality`, `data-tracking-mode`, and a once-per-second `data-performance` summary including tracker frame count and inference time. `?quality=low&profile=1` forces the low budget for diagnostics. These fields do not display in the interface. Performance measurements on the development machine do not substitute for tests on physical low-end devices.

`npm test` uses Node's test runner and the existing TypeScript dependency. It transpiles modules into a disposable directory. Tracker runtime stubs test event and projection logic; they do not validate camera recognition. Real browser checks are still needed for gesture quality, playback, capture codecs, and mobile layout.
